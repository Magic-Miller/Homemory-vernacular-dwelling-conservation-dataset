# Contributing

Thank you for your interest in contributing to the conservation of historic vernacular dwellings. The contribution process is currently being tested and is not yet open for unrestricted public submissions.

## Ways to Contribute

### Field photography

Photograph an eligible dwelling, provide the required permissions and basic context, and follow the [Field Photography Guide](guides/FIELD_PHOTOGRAPHY_GUIDE.md).

### Image annotation

Annotate building components, materials, and directly visible defects using the current schema and the [Annotation Guide](guides/ANNOTATION_GUIDE.md).

### Professional review

Review existing annotations and add clearly qualified conservation knowledge according to the [Expert Review Guide](guides/EXPERT_REVIEW_GUIDE.md).

### Documentation and tooling

Suggest improvements to terminology, translations, documentation, validation tools, and dataset-access methods. Proposed changes should preserve existing identifiers and release reproducibility.

## Before Contributing

Contributors must:

- follow applicable laws and site-access rules;
- respect owners, occupants, communities, and culturally sensitive places;
- submit only material they are authorized to contribute;
- complete the [Contribution and Consent Form](CONTRIBUTION_AND_CONSENT.txt) before material is approved for public release;
- avoid presenting assumptions as observed facts;
- accept that submissions may require redaction, restricted access, correction, or rejection.

## Contribution Channels

### Email for field data

Use email for original field photographs, the completed consent form, basic case information, and any private permission evidence. Email review takes place before the material is assigned public dataset IDs or becomes eligible for public release.

### GitHub Pull Requests for public technical contributions

Use a GitHub Pull Request for:

- documentation and translation improvements;
- code and validation tools;
- proposed vocabulary or schema changes;
- annotation corrections or assigned annotation work for images that have already passed intake and received stable IDs;
- other material that is already approved for public collaboration.

Do not include unreviewed source photographs, completed consent forms, signatures, contact details, exact private locations, or other sensitive material in a GitHub issue, commit, fork, or Pull Request. A Pull Request does not replace field-data intake or consent review.

## Email Submission Process

The MVP uses email for field-data submissions. The dedicated project submission email address will be added here before submissions open.

For one building case:

1. Download [`CONTRIBUTION_AND_CONSENT.txt`](CONTRIBUTION_AND_CONSENT.txt).
2. Type your answers into the file and mark your choices with `[X]`.
3. Create one email for the building case. Use the subject `Historic Dwelling Submission - city or region - contributor name`.
4. Attach the completed consent form and the original full-resolution photographs. Do not rename, resize, compress, or edit the photographs.
5. Send the email to the project submission address. Do not submit private material through GitHub issues or pull requests.

If the photographs exceed the email attachment limit, split them across several emails using the same subject followed by `Part 1 of 3`, `Part 2 of 3`, and so on. Attach the completed form to the first email. A maintainer will reply with a `submission_id` after the files are received.

Normally submit one form for one building case. Use another form when photographs in the same case have different creators, permissions, attribution choices, or location restrictions.

## Pull Request Process

Before opening a Pull Request:

1. Confirm that the proposed contribution belongs to one of the public technical-contribution categories above.
2. For annotation work, use only the assigned image IDs, instance IDs, filenames, schema version, and controlled vocabulary.
3. Keep unrelated changes out of the Pull Request and explain what was changed.
4. Confirm that no private or unreviewed material is present in the branch, commit history, or Pull Request description.

Maintainers may request corrections, move a proposal to private review, or close a Pull Request that contains material not suitable for public collaboration.

## Review and Attribution

Contributions may be reviewed for scope, quality, privacy, and consistency. Attribution and consent options are defined in the [Contribution and Consent Form](CONTRIBUTION_AND_CONSENT.txt) and may be refined following jurisdiction-specific review before public data collection begins.

## Questions and Proposed Changes

Once the GitHub repository is public, documentation proposals and non-sensitive questions should use GitHub Issues or pull requests. Privacy-sensitive matters must use the private contact route that will be published before launch.
